Study Notes: MySQL Indexes and B+ Trees ​

An index is an auxiliary lookup structure built from a table and organised as a B+ tree — like the table of contents of a book. With an index there is no need to walk the whole table, and queries get dramatically faster.

What an index is ​

An index stores a column (or a set of columns) of a table and generates special pointers for those values, so the whole table does not have to be traversed.

MySQL uses a B+ tree. Here is the logic of index storage (assuming a node holds at most 4 keys):

  • The leaf nodes use a clustered index and can hold the row data directly;
  • the root node uses primary-key nodes, holding the indexed column and the primary key.

When data comes in, the root node navigates: it looks for the primary key matching the indexed column, and once it is found, it returns the secondary lookup for that primary key.

Types of index ​

Primary index ​

A primary index is built on the primary key column, so a table can only have one primary index (a table has only one primary key).

sql
CREATE TABLE table_name (
  ....
  PRIMARY KEY (index_column_1) USING BTREE
);

Unique index ​

A unique index requires the indexed rows to be unique:

sql
INSERT INTO users(email) VALUES ('a@b.com'); -- ✅
INSERT INTO users(email) VALUES ('a@b.com'); -- ❌

Creating it with the table:

sql
CREATE TABLE table_name (
  ....
  UNIQUE KEY(index_column_1, index_column_2, ...)
);

It can also be added after the table exists:

sql
CREATE UNIQUE INDEX index_name
ON table_name(index_column_1, index_column_2, ...);

Plain index ​

A plain index is built on an ordinary column: the column does not have to be the primary key, nor does it have to be unique.

With the table:

sql
CREATE TABLE table_name (
  ....
  INDEX(index_column_1, index_column_2, ...)
);

After the table exists:

sql
CREATE INDEX index_name
ON table_name(index_column_1, index_column_2, ...);

Prefix index ​

If a VARCHAR(255) column has to be indexed, a prefix index can be used to optimise performance.

sql
CREATE TABLE table_name (
  column_list,
  INDEX(column_name(length))
);

Creating a prefix index after the table exists:

sql
CREATE INDEX index_name
ON table_name(column_name(length));

Composite index ​

Putting several columns into one index gives a composite index:

sql
CREATE INDEX index_product_no_name ON product(product_no, name);

Note

Whether the index is single-column or composite, the B+ tree structure is the same: non-leaf nodes hold navigation keys, leaf nodes hold the actual content. The only difference is what the key is — one column for a single-column index, a combination of columns for a composite index.

Composite indexes follow the leftmost prefix rule: if the index is (a, b, c), then the where clause has to go a → b → c.

Dropping an index ​

sql
DROP INDEX idx_name ON users;

Designing good indexes ​

  1. Pick columns with better uniqueness — values like name, phone or id;
  2. Keep indexes short; a prefix index is usually a good idea;
  3. Do not index every select — index the ones that are used often.

The index is the data, so creating too many indexes will lead to an increase in data volume.

An index is a balanced tree. When we update data, the index is also frequently performing page splits and merges, which is very time-consuming.
