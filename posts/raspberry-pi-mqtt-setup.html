Raspberry Pi + MQTT: Basic Concepts and Installation ​

A step-by-step log of turning a Raspberry Pi into an MQTT broker: flashing the SD card, getting the board online, installing Mosquitto, and securing it with a password.

1. Flash the SD card first ​

Before doing anything else, the SD card has to be flashed on a PC. A USB card reader is the easiest way to connect it to the computer.

Once the card is connected, download Raspberry Pi Imager from the official site: Raspberry Pi software – Raspberry Pi.

2. Use a phone hotspot for the first boot ​

For the initial setup I used my phone's hotspot as the network.

Remember

In the Customisation tab you have to fill in every field. Setting only the Wi-Fi name and password is not enough.

3. Boot the Pi and find its IP address ​

When flashing is done, put the SD card back into the Raspberry Pi, connect the power, and turn on the phone hotspot.

Then check the connection details of the hotspot on the phone and look for the Raspberry Pi's IP address. Mine was 10.24.199.94.

4. SSH into the Pi ​

bash
ssh emola15@10.24.199.94

emola15 is the username.

5. Install Mosquitto ​

bash
sudo apt install mosquitto mosquitto-clients

Then make sure Mosquitto starts automatically on boot:

bash
sudo systemctl enable mosquitto

6. Create a broker user ​

bash
sudo mosquitto_passwd -c /etc/mosquitto/passwd pat

This creates a new user pat and sets its password. You will be asked for the password twice; it is then encrypted and saved to /etc/mosquitto/passwd.

7. Fix ownership and permissions ​

bash
sudo chown mosquitto:mosquitto /etc/mosquitto/passwd

This changes the owner of the password file to the mosquitto user.

bash
sudo chmod 640 /etc/mosquitto/passwd

This allows read and write for the owner and read-only for the group.

8. Configure mosquitto.conf ​

bash
sudo nano /etc/mosquitto/mosquitto.conf

Add these three settings:

ini
listener 1883 0.0.0.0
allow_anonymous false
password_file /etc/mosquitto/passwd

The first line allows remote connections, the second line enables authentication, and the third line tells the broker whose credentials are allowed to publish and subscribe within the network — the user pat in my case.

9. Restart the broker ​

bash
sudo systemctl restart mosquitto

MQTT has to be restarted after the configuration file is modified.

11. Subscribe on the Pi to verify ​

bash
mosquitto_sub -h 10.24.199.94 -t apple -u pat -P 88888888 -v

This subscribes to the topic apple on the Raspberry Pi and waits for incoming messages.

With that, the whole loop works: the phone publishes, the broker on the Pi delivers, and mosquitto_sub prints the message.
